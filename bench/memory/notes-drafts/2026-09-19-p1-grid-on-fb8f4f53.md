## What ran

The memory benchmark's P1 grid had not been re-measured since the
platform merged its batch-reconcile / provisional-verdict / supersede
work and redeployed. Today two arms ran fresh, end to end, against the
deployed master, at the grid's standard regime: 50 items
(first-n deterministic selection), retrieval budget 5, hybrid
retrieval, one memory row per haystack session, embedding coverage
waited to 100% before any read, answers from a temperature-0 27B
open-weights model, labels from a different-family ~19B local judge.

- **no-memory** — answers from the question alone. n=50.
- **memory (raw ingestion)** — one stored row per session in a
  run-scoped namespace, hybrid search at budget 5. n=50.

**Determinism gate (passed).** The no-memory arm was re-run from
scratch in a second run: 50/50 answers byte-identical, 50/50 labels
identical. Same-day counts are readable.

## The grid

| family | n | no-memory | memory (raw) |
|---|---|---|---|
| single-session-user | 6 | 0.333 | 0.500 |
| single-session-assistant | 5 | 0.000 | 1.000 |
| single-session-preference | 7 | 0.071 | 0.071 |
| multi-session | 12 | 0.083 | 0.167 |
| temporal-reasoning | 5 | 0.200 | 0.400 |
| knowledge-update | 15 | 0.200 | 0.400 |
| abstention | 7 | **1.000** (7/7) | 0.571 (4/7) |
| **overall p1** | 50 | **0.150** | **0.370** |

Family score = (exact + 0.5 × partial) / n. Raw counts are in the
receipt.

**Provisional machinery:** the fallback share — answers produced in a
degraded retrieval mode — was 0/50 for the memory arm (bound: 0.05).
No cell is marked provisional; no verdict falls to UNDECIDED.
Retrieval mode observed: hybrid on all 50 reads.

**Cost stamps:** ingestion wrote 2,355 documents → 7,767 stored rows in
18.5 s; the embedding-coverage wait settled at 829 s. Answer phase:
93 s (no-memory) / 1,300 s (memory). Judge: zero unparsed replies.
The run cost $0 — every model call (answerer, judge) is local. No
metered API was used anywhere in the run.

**The honesty cell.** Seven items in this slice have gold answers that
state the information is unavailable; the label rule scores a clean
decline as exact and an invented assertion as wrong. The no-memory arm
declines cleanly 7/7. The memory arm invents on 3/7 — retrieval handed
it adjacent material and it asserted the unavailable fact. This is the
memory-side failure mode the honesty axis exists to catch: memory done
wrong is worse than no memory, on exactly the items where a confident
wrong answer costs the most.

## Reading against the previous read — three caveats

1. **Different day.** The previous read (09-18) was a different
   session on different serving conditions; only sign claims carry
   across.
2. **Different rubric stamp.** The previous quoted cells were labelled
   under judge-prompt.2; this run's labels are stamped

   Fact-family cells are therefore same-prompt comparable; the

3. **Not the hero comparison yet.** The banked timeline-arm read
   (0.400 under v2 on 09-18) predates both this master and this rubric

Banked context numbers (prior days, prior rubric — not comparable

## Method

One harness, regime-stamped, receipt-gated. Every row and the receipt
carry the full stamp: date, code sha (clean tree at the deployed
merge), dataset file + sha256 + licence, answerer and judge with
prompt sha256s, retrieval budget and observed mode, platform version
and embedding stack, selection rule. The judge classifies each gold
first (dataset marker where present; otherwise one yes/no call over
the gold alone) and then applies the matching rubric; unparsable judge
replies count as wrong and are reported. Rows are purged from the
store after the run unless kept; the namespace is run-scoped and
leaks nothing in or out.

**Rubric status, stated plainly:** the deployment's judge rubric
(judge-prompt.4) is under a pre-committed adoption gate that it did
not pass on its validation run (18/20 hand agreement, bar 19/20); the
grid's fact-family cells remain same-prompt comparable to the quoted
v2-era numbers, and this run's receipt is provisional until a
hand-scored agreement set is recorded against it (that scoring is the
director's; the receipt renders it, it is not typed).

## Open items (why the grid is not complete here)

- **timeline arm** — the hero comparison (timeline vs raw) needs a
  fresh n=50 write on this master: measured per-candidate reconcile
  cost is ~7–9 h on the serving box, which does not fit a bounded
  session. It is a single-sitting run (its checkpoints do not survive
  to a new run id). The batch-reconcile cost lever exists behind its
  flag but stamps a different regime — that is a program decision, not
  a default.
- **zep/graphiti** — never measured at n=50 anywhere. Same
  single-sitting constraint (per-question checkpoints die with the run
  id), plus a one-time environment install. Needs a dedicated window.
- **letta** — not runnable here: the arm requires an external
  PostgreSQL+pgvector server no address is configured for. Installing
  that server is a director decision recorded in the harness docs.
- **mem0** — banked n=50 evidence exists from 09-09 (prior platform,
  prior rubric). A fresh re-measure is a ~4 h single-sitting run.
